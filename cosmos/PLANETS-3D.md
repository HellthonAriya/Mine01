# ساختِ مدلِ سه‌بعدیِ سبک برای سیاره‌ها (Sprite-Sheet)

سیاره‌ها الان با CSS شبیه‌سازی می‌شوند (کره + سایه + باندِ چرخان). برای حسِ
**واقعاً سه‌بعدی و چرخشِ طبیعی** بدونِ سنگین‌کردنِ صفحه، از روشِ **sprite-sheet**
استفاده می‌کنیم: یک مدلِ سه‌بعدی را یک‌بار رندر می‌کنی، فریم‌های چرخشش را کنارِ هم
در یک تصویر می‌چینی، و مرورگر فقط همان یک تصویر را نشان می‌دهد و با اسکرول فریم
عوض می‌کند. هیچ WebGL/Three.js‌ای لازم نیست — فقط یک عکسِ بهینه.

> چرا Three.js نه؟ چون ~۶۰۰KB جاوااسکریپت + GPU + مدل را به صفحه اضافه می‌کند و
> با فلسفهٔ «بدونِ وابستگی و سبک» این پروژه جور نیست. یک sprite-sheetِ WebP برای هر
> سیاره معمولاً ۸۰ تا ۲۰۰KB است و روی موبایل هم نرم اجرا می‌شود.

---

## مرحله ۱ — ساختِ مدل و رندرِ چرخش

با هر ابزاری که راحت‌تری (همه رایگان):

- **Blender** (پیشنهادی): یک کرهٔ UV (`UV Sphere`) بساز، یک تکسچرِ سیاره روش بگذار،
  یک نورِ خورشیدی (Sun) از یک سمت بتابان.
- یا سایت‌های آماده: `poly.pizza`، `sketchfab.com` (مدلِ سیارهٔ رایگان)، یا
  تصویرِ بافتِ سیاره از `solarsystemscope.com/textures` روی کره.

**رندرِ گردشِ ۳۶۰°:**
1. دوربین ثابت، نور ثابت؛ فقط کره دورِ محورِ عمودی‌اش بچرخد.
2. یک انیمیشنِ ۳۶۰ درجه در **N فریم** بساز. عددِ خوب: **۴۸ فریم** (هر ۷.۵°).
   - کمتر (۲۴) = سبک‌تر ولی چرخش پله‌ای‌تر.
   - بیشتر (۷۲) = نرم‌تر ولی سنگین‌تر.
3. هر فریم را **مربع** و با **پس‌زمینهٔ شفاف** (آلفا/PNG) رندر کن. اندازهٔ هر فریم:
   **۲۸۰×۲۸۰ پیکسل** کافی است (روی صفحه حداکثر ~۴۴۰px با DPR۲ دیده می‌شود).

> نکته: نور را از **بالا-راست** بتابان تا با نورپردازیِ صحنه هماهنگ باشد
> (های‌لایتِ CSS فعلی هم از همان جهت است).

---

## مرحله ۲ — چیدنِ فریم‌ها در یک نوارِ افقی

همهٔ فریم‌ها را **در یک ردیفِ افقی، کنارِ هم** بچسبان (frame ۰ سمتِ چپ … frame
آخر سمتِ راست). نتیجه یک تصویرِ پهنِ `N×۲۸۰ در ۲۸۰` می‌شود.

- در Blender می‌توانی خروجی را PNG sequence بگیری و با دستورِ زیر بچسبانی
  (ImageMagick):
  ```bash
  montage frame_*.png -tile x1 -geometry +0+0 -background none planet_brew.png
  ```
- بعد به **WebP** تبدیل کن تا حجم کم شود:
  ```bash
  cwebp -q 82 planet_brew.png -o planet_brew.webp
  ```
- یا سرراست: یک تصویرِ واحد بساز که N فریم در یک ردیف دارد.

فایلِ نهایی را در `cosmos/assets/img/` بگذار، مثلاً:
`cosmos/assets/img/planet_brew.webp`

## مرحله ۳ — وصل‌کردن به سیاره

در `cosmos/assets/js/menu-data.js`، به هر سیاره‌ای که مدل دارد یک فیلدِ `sprite`
اضافه کن:

```js
{
  id: "brew", fa: "قهوه و دمنوش", en: "Brews", code: "KP-01",
  accent: "#F4A93C", accent2: "#FFD98A", surf1: "#7A4A12", surf2: "#23130A",
  ring: false, tagline: "…", glyph: "cup",
  sprite: { src: "assets/img/planet_brew.webp", frames: 48 }   // ← این خط
}
```

- `src`: مسیرِ تصویرِ نوارِ فریم‌ها (نسبت به `cosmos/`).
- `frames`: تعدادِ فریم‌هایی که در تصویر چیده‌ای (همان N).

همین! بقیه‌اش خودکار است:
- اگر سیاره `sprite` داشته باشد، کرهٔ CSS خاموش می‌شود و مدلِ تو نشان داده می‌شود.
- با اسکرول فریم‌ها جلو می‌روند (حسِ چرخش) و یک چرخشِ آرامِ بی‌کاری هم دارد.
- روی موبایل و دسکتاپ یکسان کار می‌کند.
- اگر `sprite` نگذاری، همان کرهٔ CSS فعلی نمایش داده می‌شود (بدونِ مشکل).

در پنلِ مدیریت هم می‌توانی بعداً همین مقدارها را ویرایش کنی (در صورت نیاز
می‌توانم فیلدِ sprite را به فرمِ ادمین هم اضافه کنم).

## توصیه‌های بهینگی

- هر sprite-sheet را زیرِ **~۲۰۰KB** نگه دار (WebP کیفیتِ ۸۰–۸۵).
- ۴۸ فریم تعادلِ خوبِ نرمی/حجم است؛ اگر موبایل کند شد، ۲۴ فریم بزن.
- اندازهٔ هر فریم را از ۲۸۰px بزرگ‌تر نکن مگر سیاره خیلی بزرگ دیده شود.
- همهٔ سیاره‌ها لازم نیست مدل داشته باشند؛ می‌توانی فقط چندتایش را مدل بدهی و
  بقیه روی کرهٔ CSS بمانند — با هم سازگارند.
